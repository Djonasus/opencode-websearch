# opencode-websearch

Бесплатный веб-поиск для [opencode](https://opencode.ai) без API-ключей и без MCP-сервера.
Плагин добавляет два инструмента: `web_search` (поиск) и `web_open` (чтение страниц).

## Что внутри

| Слой | Реализация |
|---|---|
| Основной движок | `html.duckduckgo.com/html/` (+ автоматический повтор через `duckduckgo.com/html/`) |
| Резерв 1 | `bing.com/search` с прогревом cookies (без них Bing отдаёт пустую страницу) |
| Резерв 2 | `lite.duckduckgo.com/lite/` |
| Резерв 3 | `bing.com/search?format=rss` |
| Новости (по запросу) | Google News RSS |
| Опционально | локальный SearXNG (`SEARXNG_URL`) — встаёт первым в цепочке |
| Чтение страниц | свой HTML→текст; для JS-сайтов и PDF — `r.jina.ai` |

Зависимостей нет: только `fetch`, `node:*` и `@opencode-ai/plugin`.

## Установка

Собранный плагин уже лежит в `~/.config/opencode/plugins/websearch.js`.
opencode подхватывает всё из этой папки при старте — конфиг править не нужно.

Пересборка после изменений:

```powershell
cd opencode-websearch
bun run build.ts
```

Другой путь для сборки: `WEBSEARCH_PLUGIN_DIR=/path/to/plugins bun run build.ts`.

## Инструменты

### `web_search`

```
query        строка, обязательна (понимает "кавычки" и site:)
count        1..20, по умолчанию 8
site         ограничение доменом: github.com, opencode.ai
recency      day | week | month | year
region       ru-ru, us-en — язык/регион выдачи
engine       auto | duckduckgo | bing | bing-rss | ddg-lite | news | searxng
```

Ответ — компактный список: заголовок, URL, сниппет (≤240 символов), домен/дата,
плюс строка `engine:` и заметки о том, какие движки были недоступны.

### `web_open`

```
urls         1..4 URL
max_chars    лимит символов на страницу (по умолчанию 6000)
```

Возвращает текст страницы без навигации и скриптов. Если HTML пустой (SPA) или это PDF —
автоматически читает через `r.jina.ai`. Локальные и приватные адреса блокируются (SSRF-guard).

## Поведение и ограничения

- DuckDuckGo режет по IP после 2–3 быстрых запросов (`202` + анти-бот). Плагин держит паузу
  3.5 с между запросами, один раз повторяет через второй фронтенд, затем помечает движок
  на паузу (60 с, с экспоненциальным ростом) и уходит на резерв.
- Bing без cookies отдаёт пустую страницу: плагин сначала прогревает `bing.com`, cookies живут 25 минут.
- Повторные одинаковые запросы берутся из кэша: поиск 10 минут, страницы 60 минут
  (`~/.cache/opencode/websearch/cache.json`, LRU на 300 записей).
- В системный промпт добавляется одна строка-подсказка, чтобы модель пользовалась `web_search`.
  Отключить: `WEBSEARCH_NO_HINT=1`.
- Заменить встроенный `websearch`: `WEBSEARCH_OVERRIDE_BUILTIN=1` (добавляется алиас).
- Свой SearXNG: `SEARXNG_URL=http://localhost:8888`, в `settings.yml` —
  `search.formats: [html, json]`. В Docker:
  `docker run -d -p 8888:8080 -v $PWD/searxng:/etc/searxng searxng/searxng`.

## Проверка

```powershell
bun test              # 28 юнит-тестов на фикстурах, без сети
bun run scripts/smoke.ts   # живой прогон: 5 запросов + чтение страницы
```

Живой прогон специально сделан «злым»: 5 запросов подряд провоцируют анти-бот, поэтому
часть движков уйдёт в cooldown — это ожидаемо, важен итоговый непустой ответ.

## Оговорка

Скрейпинг DuckDuckGo и Bing нарушает их условия использования. Речь о личном
низкочастотном использовании: плагин сознательно тормозит себя, кэширует ответы и не
ходит в поиск без запроса. Для регулярной нагрузки используйте SearXNG или бесплатный
ключ Brave/Tavily — адаптеры добавляются в `src/engines/` за несколько строк.
